# 蓝V合作方收款与履约网关

独立运行在我方 X 服务器。AI京东只接服务端 API，不部署履约程序，不接触卡台、X Cookie 或支付宝私钥。

公开入口为 `https://api.quefa.cn/bluev`，通过 Quefa 的专用路径转发到 `https://x.aifu.me/partner`。原 GPT 接口和原 X 卡密系统不变。

## 接入

- [完整接口说明](docs/x-partner-api.md)
- [Node.js 服务端示例](docs/examples/x-partner-client.mjs)
- 商品 `x_premium_3m` / `x_premium_6m`，人民币供货价 22 / 44。
- 客户先确认 X 用户名，再扫码付款；验签并确认到账后，系统自动创建唯一赠送任务。
- 平台初期轮询查单；平台通知默认关闭，不影响支付宝的收款通知。

## 开发验证

需要 Node.js 24。独立执行 `npm ci`、`npm run check`、`npm run build`。
测试使用模拟支付与隔离临时数据库，不发起真实充值。

此目录由已有平台网关提取，保留支付、财务和幂等回归测试。生产只加载两个蓝V商品；所有旧 GPT 商品均不在此独立实例开售，后台和开发接口不对公网公开。

## 发布边界

发布脚本与门禁说明见 `deploy/README.md`。初始商品、销售门禁和工作进程门禁均关闭；正式开售前需与接入方联合验收，并确认允许零售价范围。当前 9999 元上限仅是未开售配置占位，不代表已授权的销售范围。

`PARTNER_SALES_GATE_FILE` 控制新增订单，关闭不妨碍原单查询。`QUEFA_WORKER_GATE_FILE` 是工作进程启动门禁，移除后不会停止已启动的工作进程。不要关闭补查来处理已付款订单。

合作方独立商户的 3000 点是履约额度，不是人民币余额。待付款二维码目前不会预占点数，首批联调需要控制并发，避免超额度收款。成本未录入时显示待核算，不把供货款全部当利润。

原 Quefa 商品中心里的蓝V条目是待接入展示。此独立接口中的报价才是新订单依据；两者当前不自动同步，后续调价应先关闭销售并同步核对。

密钥、数据库、环境和构建输出不得提交。新服务不得读取旧 X 数据库或旧主加密密钥。初始化仅由服务器管理员在同机内解密收款配置，生成全新的独立环境。

## 蓝 V 独立测试入口与收款配置

后台登录后进入 `https://api.quefa.cn/admin/bluev-test`。测试订单和支付宝配置分为两个页签；配置直达地址为 `https://api.quefa.cn/admin/bluev-test#alipay`。

- 此配置仅供 `x-bluev-sandbox` 独立蓝 V 测试收款使用，不修改旧京东/GPT 收款、X 卡密系统或正式合作方网关的配置。
- 填写正式环境 App ID、商户 PID、应用私钥和支付宝公钥。仅支持 RSA2 公钥模式；支持 PEM 或纯 Base64 密钥，不支持证书模式。不要把应用公钥误填为支付宝公钥。
- 同一个 App ID / PID 的密钥留空表示保留；更换应用或商户必须同时提供两项密钥。密钥不回显、不保存在浏览器存储；服务器使用独立加密密钥加密保存版本历史。
- 保存前仅校验格式和 RSA 密钥，**不等于已验证当面付权限或实际出码成功**。保存不创建付款、不自动启用接单，不影响原订单金额、账号或有效期。
- 新订单绑定当时的收款身份。更换收款身份后旧单仍按原身份查单；同身份更新密钥后，原单查询使用该身份最新密钥，延迟回调支持历史公钥验签后再主动查单。
- 通知地址固定为 `https://x.aifu.me/bluev-sandbox/callbacks/alipay`，不允许在页面修改。

未取得付款码的测试单，原付款窗口结束至少 60 秒后，可由管理员“核对并关闭测试”。后端只有在支付宝已验签查单确认交易不存在、且没有并发处理或付款证据时才关闭；不删除原单、不退款。已生成付款码、已付款或结果未知的交易不能用此操作强行关闭。关闭释放测试名额，历史仍可查看。异常晚到账保留证据并转人工核对，不自动赠送。

升级使用 `deploy/upgrade-bluev-test.py`，仅替换两个独立测试服务，不重启旧交易容器、不改代理。已保存新收款版本或关闭测试单后，禁止回退到不支持这些数据的旧代码；永不通过恢复数据库回滚业务记录。
