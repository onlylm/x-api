# 管理员人工确认付款

在“订单与队列 → 直接赠送”选择“人工确认付款”，再选择扣点商户、接收账号、套餐和本单银行卡。使用系统主卡时，也会将这张主卡固定到本单；人工模式不自动切换备用卡、不自动开卡或充值。

下单复用商户点数冻结、资格检查、每日限额和 FIFO 队列。系统创建 X 付款会话、验证商户及一次性产品金额、准备 Stripe 支付方式后，停在 `awaiting_approval`。这是准备支付，不是提交扣款。待确认订单仍占据执行队列，后续订单保留排队。

管理员在订单详情核对账号、BDT 金额和银行卡 ID，输入 `CONFIRM_PAYMENT` 再点击“确认付款”。接口只持久化原单授权，不直接调用付款 API；队列重查资格、金额、卡状态、暂停锁和授权有效期后，沿用原会话及支付方式提交一次。授权五分钟内有效，失效需重新确认；提交后的结果未知或 3DS 只核对原单，不再次授权付款。

人工模式只由管理员入口授权，不能从商户 API 或卡密兑换入口启用。模式和银行卡绑定使用现有加密且不可变的 `orders.payment_card_selection`，不增加数据库迁移。确认授权写入加密执行记录和一次性审计，受原单状态、工作令牌、租约及确认金额/账号/卡编号约束。

这不是在跨域 Stripe 页面自动填表。银行卡由服务器向 Stripe 准备为支付方式，最终人工点击发生在本系统后台。原 Stripe 页面仅在提交后用于查看或补充验证，不向浏览器返回 PAN、CVV、支付方式令牌或付款私钥。已关闭订单不会因新功能恢复执行。
